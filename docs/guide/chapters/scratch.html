Making an animal from scratch: a rhino

This chapter builds a creature that did not exist before: a crude rhino. The shape is not the point; the point is that every stage of a from-scratch creature is done once, in order, with the add-on's own tools: New Creature (From Scratch), shaping the control net, a horn with its own bone and skinning, a look at the limbs and connection rings, an animation, Validate, Combine Preview against a stock creature, Export, and finally a load test in the real Object Editor. Every screenshot below was taken from the capture script docs/guide/capture/chapters/ch_scratch.py, which is a scripted version of the same clicks.

What the scaffold gives you

New Creature (From Scratch) does not hand you an empty scene. It writes a complete, rulebook-clean creature to the .sgm you pick and imports it through the normal import path, so that file is the object's source exactly as for an imported stock creature. At Detail 1 it contains:

  • the canonical 48-bone skeleton (pelvis, spine1-3, neck1-3, head, jaw, nose, ears, tail1-4, the four leg chains, plus the wing and arm stub bones every stock creature carries);
  • a connected body: torso, head, tail and four legs as one closed quad cage turned into 248 bicubic patches over 2234 control points, so it is watertight and the Object Editor loads it as it is;
  • 13 limbs (Torso, Head, Tail, four legs with patches; L/R side wing, L/R top wing and L/R front arm as bone-only stubs) and 12 connection rings in the stock layout (6 corners for head and tail on neck1 / pelvis, 4 for the legs and the stub sockets), which is what the game's combiner grafts at;
  • a labelled checker texture with cylindrical UVs per body part, so the creature is obviously yours;
  • the 9 standard clips (Idle1, walk, run, melee1, meleelow1, oattack1, crouch, stumbledie, stumblegetup) as procedural motions, imported as Actions on the rig, and the base-game IK chains.

The file dialog has five options: Name (limbs, rings and the texture are named after it), Detail 1-3 (sections per body span; 1 is the coarsest scaffold), Standard Clips, IK Chains and Clips as Actions. Leave them at their defaults for this chapter.

1. New Creature (From Scratch)

  1. In the 3D Viewport press N and open the SGM tab of the sidebar.
  2. Click SGM Native Patches > New Creature (From Scratch) (the same entry is in Add > Impossible Creatures Creature (From Scratch)).
  3. In the file browser set Name to Rhino, keep Detail 1, pick a folder and file name (rhino.sgm) and confirm. The creature is written, imported, framed and selected; the info line reports New creature Rhino: 2234 control points, 248 patches, 48 bones, 12 rings, 9 clips -> rhino.sgm (rulebook clean).
  4. Display box: switch the shading dropdown from Textured to By Limb and tick Show Connections to see what you got.

2. Shape it in Edit Mode

The object's vertices are the file's control points, so Blender's ordinary Edit Mode tools reshape the creature. Every patch shares its corner and handle points with its neighbours, so whatever you drag stays watertight. The scaffold comes with X-Mirror Editing on, so a move on one side moves its mirror partner.

  1. Tab into Edit Mode. Tick Show Handle Dots in the Display box: corners are gold, handles blue.
  2. Select a region and press G to grab, S to scale. Pick regions by body part: Boner > Limbs > Select Limb selects every point of a limb's patches (or box-select in a side view, Numpad 3). Proportional editing (O) helps to keep things smooth.
  3. For the rhino the capture script did, in one go: squashed everything to 78 % height (shorter legs, lower body; the feet stay on the ground), widened everything by 35 %, scaled the torso-only points into a barrel, scaled the head by 1.35 about the neck ring and dropped it 12 cm, shortened the tail to 45 % and let it droop, and thickened each leg by 30 % about its own axis.
  4. Tab back to Object Mode to judge the shape.

Moving points does not move bones. The skeleton is edited separately (select the rig, Edit Mode on the armature, move bones; Export rewrites only the bones you moved and keeps the shape). For a first creature it is fine to leave the bones where the scaffold put them: skinning is by ownership, not by bone position, and the clips still play. Validate will, however, warn that the 9 kept clips have bounds from the source geometry, whose extent changed: the engine culls by clip bounds, so once the shape is final, edit or re-key a clip to have it re-encoded with fresh bounds.

3. A horn: pull it out, give it a bone, skin it

The brief said "Extrude Patch a head patch". That does not work on the scaffold: Extrude Patch grows a new patch from an open patch side, and the scaffold is closed (every side is shared by two patches), so the button in the Modeling box is greyed out with that reason. A horn is made the other way round: pull existing head points out, then give them a bone.

  1. Edit Mode, front three-quarter view. Select the top-front control points of the head cap (22 points here: the upper half of the cap and the first ring behind it). With X-Mirror Editing on, selecting one side selects both.
  2. G and drag them forward and up (the script moved them 0.28 m forward and 0.32 m up). The cap bulges into a horn. Leave the points selected.
  3. Object Mode. In Boner > Bones set the Bone field to head (type it, or use the eyedropper Pick Bone and click a head point). Click Add Bone under Active; in the dialog set Name to horn, an Offset from the head bone's tail (in the head bone's axes) and a Length (0.25 m here), and confirm. The report says Added bone 'horn' under 'head', in limb 'Rhino_Head'; horn becomes the active bone and the tab shows pending: added horn (an added bone Export will write) and horn · 0 points · parent head.
  4. Tab back into Edit Mode with the horn points still selected and click Assign Selected. The line becomes horn · 22 points · parent head and the By Bone overlay (the Bones tab switches to it) colours the horn points bright in the horn's colour, the rest dimmed.

The Add Bone dialog's Offset is measured from the parent bone's tail in the parent's own axes, so a horn under head usually needs a negative value along the bone's own axis (the scaffold's head bone points down, not forward). If the bone lands in the wrong place, select the rig, enter its Edit Mode and move the bone: it is an added bone, so it may also be re-parented or deleted again; the limb lists follow.

4. Limbs and connections

The scaffold already has the standard limb set and one connection ring per socket, so this stage is a check, not a build. Both live in the Boner sub-panel (below the SGM panel; scroll the sidebar down).

  1. Boner > Limbs lists the 13 limbs with Boner's class label, patch and bone counts and a status: Torso 100 patches / 5 bones, Head 32p / 11b (the horn is in it now), Tail, four legs, and six stub limbs (0 patches, 1 bone) for the wings and arms.
  2. Click a limb's name to make it active; the boxes below show its classification (Side / Position / Plane / Type / Non-Swappable) and its bones, with Select Bones, Set Root Bone, Add / Remove Active Bone.
  3. Click Rename, type Rhino_HornedHead, confirm. Only the name changes; the rulebook and the combiner key on the class (0x40 = Head), never on the name.
  4. Boner > Connections lists the 12 rings as Parent > Child · corners · host bone (Torso > Head 6/6 · neck1, Torso > Tail 6/6 · pelvis, the legs 4/4 on spine3 / pelvis, the stub sockets 4/4). Tick Show Connections in the Display box and click the Rhino_Head row: its ring is drawn thick and bright at the neck, the other rings dimmed. Below the list: Create for Limb, Rename, Delete, Add Stub Socket, the Parent / Child boxes, the host bone with Set / Default, and in Edit Mode Pick Ring / From Selection.

5. Skinning: is every point on a bone?

The scaffold arrives fully skinned (every control point rigidly owned by the nearest bone of its part), and the shaping in step 2 does not change ownership. What can go wrong later is a point with no bone: Export refuses to write a creature whose patch points have no bone, and the Bones tab says so (Unassigned: N (N on patches: Export refuses)).

  1. Set the Display shading to By Bone (Boner > Bones does it for you): points with no bone are orange.
  2. Next to Unassigned click Select (Edit Mode) to select them.
  3. Either pick the bone they should follow and click Assign Selected, or use Auto Skin > Selected, else Unassigned to give each one its nearest bone segment. Auto Skin > Reset All re-derives the whole skin from the skeleton (a first pass; it agrees with Relic's hand skin on about half the points on stock creatures). Remove from Bone is the reverse. All of it is undoable with Ctrl+Z.

On this rhino nothing is unassigned; the horn assignment in step 3 was the only skin edit.

6. Animation

The nine clips are Actions on the rig. Loading one plays it; adding an Action adds a clip.

  1. With the creature active: Load Animation > Idle1 (rig box in the SGM panel). It becomes the active Action, the scene range follows the clip and the panel reads active: Idle1. Space plays.
  2. To see the keys, turn the Timeline into a Dope Sheet (Editor Type menu at its left, or drag its top edge up first to make room) and untick Only Show Selected in its filter, or click Select Rig and use the Action Editor. Each clip frame is one key.
  3. A new clip: select the rig, create a new Action (Dope Sheet > Action Editor > New), name it headbob, enter Pose Mode (Ctrl+Tab), and key neck2, neck3 and head at frames 1, 11 and 21 (I > Rotation) with the head pitched down at frame 11. The script did exactly that: 21 frames, three keyed bones.
  4. Scrub to frame 11: the head dips. Export writes this Action as a tenth clip; the nine imported clips are kept byte-for-byte because they were not touched.

An Action counts as a clip when it belongs to the rig: the rig's active Action, an Action on one of its NLA tracks, or one stamped for it at import. A new Action you keyed and then dropped (held only by its fake user, on no track) is not exported; Export's warnings say so and how to include it.

7. Validate, Combine Preview, Export

  1. Tools > Validate (will it load?) with the dropdown next to it on Quick (Combine Checks). The verdict goes to the status bar and the Info log (Editor Type > Info). For this rhino nothing blocks loading and nothing is missing from the stock rulebook; the log lines were:
    • WARN export: 9 kept clip(s) have bounds from the source geometry, whose extent changed (the engine culls by clip bounds): edit or re-key a clip to re-encode it
    • COMBINE INFO setup: default attributes, size 3 (no .lua next to rhino)
    • COMBINE WARN precheck: legs without a ground speed ['speed_max-front', 'speed_max-back']: a combine keeping them zeroes the ground speed
    • COMBINE INFO rhino: 13 designs (13 combined, 0 skipped), 0 with issues, 1.7 s; its parts grafted onto: head 6, tail 6, front_legs 5, rear_legs 6 torso(s)
    The two warnings are advisories: the first is the clip-bounds note from step 2, the second says a Blender-authored creature has no .lua attribute file, so a combine that keeps its legs gets a ground speed of zero. Neither stops the creature from loading or combining.
  2. Combine Preview (the collapsed sub-panel at the bottom of the SGM panel; click its header): Role This Creature Is the Torso, other creature Stock, pick bull in the stock list, tick only the Head part button, click Preview. The game's combiner grafts the bull's head onto the rhino at its neck ring and draws the result as a ghost beside the creature (+X). The readout for this run: Combo: rhino torso + bull Head | size 5 · ground · body scale ×1.292 · 338 patches; the Head slot bull · ×0.691 · Ring Size & Limb Bounds, every other slot this. Clear removes the ghost; Materialize… would write the combination as its own creature.
  3. Export SGM (Native Patches), file name rhino_done.sgm. The report line names every change against the scaffold file: skinning: 5 bone range(s) rebuilt (2234 points re-encoded); bones: added 1 (horn); limbs: renamed 1 (Rhino_Head -> Rhino_HornedHead); bones 1 (Rhino_HornedHead); clips: 9 kept, 1 written. The moved control points are the "re-encoded" ones; the nine imported clips keep their bytes.

8. Prove it loads

The repo's headless Object Editor harness loads an .sgm in the real editor under Proton and reports a verdict. From the repo root (with IC_INSTALL set):

.venv/bin/rdn-oe /tmp/bz_guide/scratch/rhino_done.sgm

For the file this chapter exported it printed:

LOADED  rhino_done.sgm                       7.1s  OBJECTEDITOR started at 2026-09-15 17:01; OS NT 6.2, 0MB Physical Memory
SUMMARY 1/1 loaded in the Object Editor

That is the whole workflow: a creature that never existed now loads in the game's own editor, with its skeleton, its 10 clips, its limbs and its graft rings, and combines with the stock creatures.

Not possible yet (checked against GMAX_PARITY.md and STATUS.md):

  • Building from a primitive. There is still no "add a patch box": geometry has to start from the scaffold, from a stock creature, from Convert Mesh to Creature or from Fit Patches to Mesh. Everything after that start now exists — Delete Patch, Add Quad, Fill Hole, Weld, Subdivide, Extrude Region, Mirror to Whole and Attach — so the gmax "extrude the body plan, mirror, weld" half of the flow does work; see the Topology chapter.
  • Material IDs. The per-patch material slot is stored and round-tripped but not editable, and there is no select-by-ID; the scaffold uses one material with its labelled texture.
  • Template choice. No wolf / lion reference template; the scaffold body is the only from-scratch start.
  • Animation helpers. No BoneMirror half-cycle offset, no loop-closure check, no importing rotations from another creature; keys are set with Blender's own tools.
